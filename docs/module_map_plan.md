# 学習器のマップ（可視化・組み立てツール）の検討メモ

作成: 2026-10-17。持ち主の依頼:
- 学習器の配置や繋がりを、マップで表したい。
- 最終的には、分けて学習した部品を、マップの上で組み立てられるようにしたい。
- 周波数で制御する学習器の特徴を残したい（波形化、仮入力、分岐、分配、合成）。
- 接続の種類（Raw、焦点位置、フーリエ変換済み、文字列 など）も検討してほしい。

最初から完全な仕組みは目指さず、まず必要なものから作る前提で、案をまとめる。

## 1. 名前の案（「学習器」の別名）

部品 1 つの名前と、組み上がった全体の名前を対にすると、マップの上で話がしやすくなる。

| 案 | 1 つの部品 | 組み上がった全体 / マップ | 由来・イメージ |
|---|---|---|---|
| **A（おすすめ）** | **音粒（おとつぶ）/ Grain** | **譜面（Score）** | グラニュラー合成（小さな音の粒を集めて音を作る）。小さな単位を集めて大きな働きを作る、というしくみそのもの |
| B | 共鳴子（Resonator） | 響板（Soundboard） | 特定の周波数の模様にだけ強く響く、という学習器の性質を表す |
| C | 音色（Timbre） | 和音（Chord）/ 楽曲 | 専門家ごとに得意な音色があり、重ねると和音になる |
| D | 動機（Motif） | 楽章（Movement） | 音楽の最小の意味の単位。組み合わせて曲を作る |
| E | 倍音（Overtone） | 音律（Temperament） | 基音に重なる周波数成分。周波数で振り分ける性質に近い |

おすすめは A です。「音粒」を「譜面」に並べて繋ぐ、と言えるので、組み立てツールの名前もそのまま「譜面エディタ」にできる。
以下では仮に「部品」と書く。

## 2. 部品（ノード）の種類

いまのコード（sinwave_minimal、A1 の振り分け役）にある処理を、そのまま部品に分けたもの。★ は最初に作るもの。

| 部品 | 入力 → 出力 | 中身（今のコードとの対応） | 計算（FFT 回数） |
|---|---|---|---|
| ★ 波形化 | 文字列 → Raw の光 | encode_wave（wave / rainbow / color / coh、L、V、T、文字数） | 0 |
| ★ 仮入力 | なし → 文字列 または Raw | 試しに流す文字列、データ集からの見本、背景光（一様な光） | 0 |
| ★ 板の束 | Raw → Raw | Sin の板 × 枚数（区画、振幅 A、初期位相 φ、ω は固定）と回折 | 2 × 枚数 × T |
| ★ レンズ | Raw → フーリエ面 | FFT（焦点面に集める） | T |
| ★ 窓（検出器） | フーリエ面 → 点数 | 窓の位置・幅、温度、背景光。クラス名のラベル | 0 |
| ★ 振り分け | フーリエ面 → 選択 | 水面の板 R1（透過率の板 M_k(f)）、上位 m 人 | 0（レンズの後なので） |
| ★ 合成 | 点数 × n → 点数 | 足す（merge の avg）、gate（担当の窓の光の割合）、log p + log-softmax | 0 |
| 分岐 | Raw → Raw × n | 同じ光を n 本に分ける（ビームスプリッタ。明るさは 1/n） | 0 |
| 分配 | フーリエ面 → フーリエ面 × n | 周波数の帯ごとに別の道へ送る（色分けの鏡、ダイクロイックミラー） | 0 |
| 透過率の板 | フーリエ面 → フーリエ面 | 周波数ごとの透過率 M(f)。分配の学習版 | 0 |
| 逆レンズ | フーリエ面 → Raw | 逆 FFT。周波数を選んだあと、また板の束に入れる | T |
| 較正 | 点数 → 点数 | 温度・下駄（A1b で試している） | 0 |
| 明るさ | フーリエ面 / Raw → 明るさ | 絶対値の 2 乗。ここで位相は失われ、戻れない | 0 |

## 3. 接続（線）の種類

線の種類ごとに色を分け、種類の合わない端子どうしは繋げないようにする。種類を変えるには、必ず部品を通す（例: Raw からフーリエ面へは「レンズ」を通す）。

| 種類 | 中身 | 形 | 色の案 | 備考 |
|---|---|---|---|---|
| ★ 文字列 | 文字の並び | list[str] | 灰 | 波形化の前 |
| ★ Raw（空間の光） | 板の上の複素の光 | (N, T, L) 複素数 | 青 | 位相を持つ。分岐・板の束の間を流れる |
| ★ フーリエ面（焦点面） | レンズの後の複素の光 | (N, T, L) 複素数 | 紫 | 位置 = 周波数。分配・透過率の板・振り分けはここで行う |
| ★ 点数 | 窓ごとの値（クラスごと） | (N, C) 実数 | 橙 | 合成・較正の入出力 |
| ★ 選択 | どの道を動かすか | (N, K) の確からしさ、上位 m の印 | 赤（点線） | 制御の線。動かさない道は灰色にし、計算量の表示から外す |
| 明るさ | 絶対値の 2 乗 | (N, L) 実数 | 黄 | 位相がないので、Raw やフーリエ面には戻せない |
| 焦点位置 | 窓の位置の一覧 | 窓の番号 ↔ 周波数の位置 | 線ではなく、窓の部品の設定として持つ案 | 窓を他の部品と共有するときに使う |

「焦点位置」は、データが流れる線というより「スクリーンのどこに何を集めるか」という約束なので、まずは窓の部品の設定として持つ。
複数の部品で同じ窓を使う必要が出たら、線の種類に昇格させる。

## 4. マップに出す情報

- 部品ごとの計算量（FFT 回数）と、道全体の合計。振り分けで動かない道の分は除いた「実際の計算量 %」（A1 の指標と同じ数え方）。
- 部品ごとの学習する数。学習済みか、凍結しているか。
- 仮入力を流したときの、各線の中身の小さな絵。
  - Raw は明るさの帯、フーリエ面はスペクトル、点数は棒グラフ。
  - SinWaveNet.trace と同じ情報を、線の上に出す。
- 端子の種類が合わない接続や、設定（L、T、V）が揃っていない部品を、赤で示す。merge が今チェックしているのと同じ条件。

## 5. しくみの案

1. **譜面ファイル（JSON）**: 部品（種類、設定、学習済みの値のファイル）、線（どの端子からどの端子へ）、位置を書く。マップと Python の共通の言葉になる。
2. **Python 側（sn2graph）**:
   - 譜面ファイル ↔ torch の部品の変換。
   - 型のチェック。
   - 部品ごとの学習（ほかを凍結して 1 つだけ学習する）。
   - 実行と計算量の数え上げ。
   - 今ある SinWaveNet・Merged・A1 の振り分けの組み合わせを、譜面ファイルとして書き出す機能。
3. **マップ（ブラウザの 1 ファイルの HTML）**:
   - 譜面ファイルを読み込んで描き、線の種類で色分けする。
   - 部品を置く・繋ぐ・設定を変える → 譜面ファイルを書き出す。
   - ノード編集の部品には、型つきの端子を持つ既製のライブラリを使うと早い。たとえば LiteGraph.js（MIT。ComfyUI で使われている）や Drawflow（MIT）。
   - 使うときは、取得元・大きさ・ライセンスを示して確認をもらってから入れる。

## 6. 段階の案（小さく始める）

| 段階 | 内容 | 終わりの目安 |
|---|---|---|
| M1 見るだけ | A1 の構成（波形化 → 振り分け R1 → 専門家 4 人 → 合成）を Python から譜面ファイルに書き出し、HTML で描く。計算量・学習する数を表示 | A1 の表と同じ計算量 % がマップに出る |
| M2 流して見る | 仮入力を 1 つ流し、各線の中身（スペクトル・点数）と、選ばれた道を表示 | 「なぜこの専門家に送られたか」がマップで見える |
| M3 組み立て | マップで部品を置き・繋ぎ、譜面ファイルを書き出し、Python で読み込んで実行・評価 | マップで組んだものが A1 のスクリプトと同じ数字を出す |
| M4 部品ごとの学習 | 部品を 1 つ選んで学習し、残りは凍結する。学習済みの部品を棚から差し込む | 専門家を 1 人足す・外す操作がマップ上でできる |

最初に作るのは、★ の部品 7 種と ★ の線 5 種で、段階 M1〜M2。
分配・逆レンズ・焦点位置の共有は、実験で必要になってから加える。
