（会話で触れられた「/mnt にあった設計案」は、この PC のこのリポジトリには無いため、検討メモと会話の内容から書いた。）

## 1. ひとことで言うと

**グレイン（波で学ぶ小さな部品）を、地図の上に「箱」として並べ、「線」でつないで、大きな仕組みを組み立てる道具**です。
電子回路の回路図や、音楽の機材をケーブルでつなぐ図を思い浮かべてください。

- 箱 = 部品（文字や絵を光にする、模様の板を通す、レンズで集める、窓で読む、振り分ける、合成する …）
- 線 = 部品から部品へ流れるもの（文字列、光の場、明るさ、点数 …）
- 地図は 1 つのファイル（**譜面ファイル**）として保存され、**絵として表示するのにも、Python で実際に動かすのにも、同じファイルを使います**。
  「絵の中の図」と「実際に動くもの」が食い違わない、というのがいちばん大事な点です

## 2. なぜ要るのか

これまでの実験（実験04）で、いちばん良かった形は次のような組み立てでした:

```
文字列 → 光にする → [共通の前段: 板 8 枚] ─┬→ レンズ → 窓 → 振り分け（上位 2 人を選ぶ）
                                         └→ 選ばれた専門家の [後段: 板 6 枚] → レンズ → 窓 → 合成（較正して比べる）
```

これを Python の中だけで書くと、どこで何が分かれ、どこが計算を食っているかが見えにくくなります。
地図にすると、①どこを流れる光がどの部品に入るか、②どの道が動かずに済んでいるか（計算量 %）、③どの部品を学習済みで固定しているか、がひと目で分かります。
最終的には、地図の上で部品を差し替えたり、専門家を 1 人足したり外したりして、そのまま動かせるようにしたい、というのが持ち主の目標です。

## 3. 線の種類（つなぎ方）

線には種類があり、**種類の合わない端子どうしはつなげません**。種類を変えるときは、必ずそのための部品を通します（例: 光の場 → 周波数の面は「レンズ」を通す）。

| 線の種類 | 中身 | たとえ | 2D で見直した点 |
|---|---|---|---|
| 文字列 | 文字の並び | 楽譜の歌詞 | そのまま |
| 絵 | 明るさの画像（0〜1） | 写真のフィルム | **2D で追加**。「絵 → 光にする」部品（振幅として・位相として）が受ける |
| 光の場（Raw） | 板の上の複素数の光。1D は (N, 色, L)、2D は (N, Ly, Lx) | 光そのもの | 形（1D か 2D か、大きさ）を線に書き、合わないとつなげない |
| 周波数の面（焦点の面） | レンズの後の複素数の光。場所 = 向き（周波数） | 虫眼鏡で集めた光の点 | 2D の 4f 系（レンズ → 板 → 逆のレンズ）がここを通る |
| 明るさ | 振幅の 2 乗（位相が消える） | 写真に写った明るさ | **2D で、ここから光に戻す部品（明るさを測って光を出し直す = 平方根の非線形）が要る**。1D の検討では「戻れない」としていた |
| 点数 | 窓（クラス）ごとの値 | 採点の結果 | 符号で読む（窓の数とクラス数が違う）場合は「窓の明るさ」と「点数」を分ける |
| 確率 | 対数の確率 | 天気予報の % | **追加**。2D の言語の実験で、確率を足し合わせる部品（重み付きの和）が出てきたため |
| 選択（制御） | どの道を動かすか（上位 m 人の印、確からしさ） | 交通整理の信号 | そのまま。動かない道は灰色にし、計算量から外す |

「焦点の位置（窓をスクリーンのどこに置くか）」は、データが流れる線ではなく「窓の部品の設定」として持ちます。
後から専門家を足すと窓が増えるので、**既存の窓の位置を動かさずに窓を足せること**が要ります（今の部品は窓の数で位置が決まるので、増やすと全部動く。[parts_wishlist.md](parts_wishlist.md) の 3）。

## 4. 部品の種類（箱）

★ は最初の版で作るもの。

| 部品 | 入る → 出る | 中身 | 計算（FFT 回数） |
|---|---|---|---|
| ★ 光にする（1D） | 文字列 → 光の場 | 虹など（sinwave_minimal の encode_wave） | 0 |
| ★ 光にする（2D） | 絵 → 光の場 | 振幅として・位相として（image_to_field） | 0 |
| ★ 仮入力 | なし → 文字列・絵 | 試しに流す見本 | 0 |
| ★ 板の束 | 光の場 → 光の場 | 板 ①〜⑤ × 枚数 + 回折。前段・後段はこれの役割の名前 | 板 1 枚 2 回 |
| ★ レンズ | 光の場 → 周波数の面 | フーリエ変換 | 1 回 |
| ★ 窓 | 周波数の面 → 点数 | 窓の位置・幅・温度・背景光 | 0 |
| ★ 振り分け | 周波数の面・点数 → 選択 | 上位 m 人を選ぶ | 0 |
| ★ 合成 | 点数 × 人数 → 点数 | 足す・自信で選ぶ・較正して比べる | 0 |
| 明るさ → 光（非線形） | 明るさ → 光の場 | 平方根など（2D で効いた） | 0 |
| 4f 系・相関器 | 光の場 → 明るさ | 鍵の模様がどこにあるか（到達点 C の注意の候補） | 2〜4 回 |
| 確率の足し合わせ | 確率 × 本数 → 確率 | 重み付きの和 | 0 |
| 照明 | 光の場 → 光の場（色の軸が増える） | tilt・アダマール（区画どうしの干渉を消す） | 照明の数の倍 |

## 5. 最初の版の範囲（M1〜M2）

| 段階 | できること | 終わりの目安 |
|---|---|---|
| **M1 見るだけ** | 実験07（2D の共通の前段 + 後段）または実験04 の構成を、Python から譜面ファイルに書き出し、ブラウザの 1 ファイルの HTML で地図として描く。箱ごとに計算量・学習する数・固定かどうかを表示 | 地図に出る計算量 % が、実験の表と一致する |
| **M2 流して見る** | 仮入力を 1 つ流し、線の上に中身の小さな絵（光の場の明るさ、周波数の面、点数の棒グラフ）を出す。選ばれた道を色で示す | 「なぜこの専門家に送られたか」が地図で見える |
| M3 組み立て | 地図で箱を置き・つなぎ、譜面ファイルを書き出して Python で動かす | 地図で組んだものが実験のスクリプトと同じ数字を出す |
| M4 部品ごとの学習 | 箱を 1 つ選んで学習し、ほかは固定。学習済みの箱を棚から差し込む | 専門家を 1 人足す・外す操作が地図の上でできる |

最初は M1〜M2 だけ。箱は ★ の 8 種、線は「文字列・絵・光の場・周波数の面・点数・選択」の 6 種から始め、明るさ → 光・4f 系・確率は実験で要るようになったら足します。
地図の部品（ノード編集）には既製のライブラリ（LiteGraph.js や Drawflow、どちらも MIT）を使う案です。入れる前に、取得元・大きさ・ライセンスを示して持ち主に確認します。

## 6. 名前

部品 1 つは「**グレイン**」（持ち主が選んだ名前、2026-10-17）。組み上がった全体と地図の名前（検討メモでは「譜面」）は、ほかの名前の統一と一緒に、持ち主と決めます。
